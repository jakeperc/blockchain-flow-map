# Make the live build affordable, honest, and multi-chain

## Context

The registry grew 30× in two days (21 → 805 wallets, 70 entities, 28 jurisdictions) but the data pipeline underneath it has not changed since it held 21 addresses. Measuring it against the real endpoints on 2026-09-19 shows the published page is considerably more expensive and less truthful than assumed:

| Feed (USDC+USDT Transfer logs) | Unfiltered | Filtered to the 805 registry addresses |
|---|---|---|
| Ethereum | **~23 MB per hour** | ~4 MB per hour |
| Base | ~100 MB per hour | ~0.3 MB per hour |
| Arbitrum | ~17 MB per hour | ~0.1 MB per hour |

So every visitor to jakepercy.com downloads ~23 MB to fill the hour on load, then ~23 MB every hour the tab stays open, from free keyless endpoints. On a phone that is punitive; at any real traffic it abuses the endpoints.

Three silent failures compound it:

1. **Failed chunks vanish.** `live-client.ts:259` is `catch{results[i]=[];}` — a rejected 2 MB chunk becomes an empty array, no health signal, no message. The published hour is very likely already incomplete and the page claims it is LIVE.
2. **The registry expires 2027-03-17.** `model.ts:38-41` rejects evidence older than 180 days; every entity is stamped `2026-09-18`/`2026-09-19` and `gen-addresses.mjs:30` hard-codes the same literal for every address regardless of input. On that date every attribution becomes inadmissible at once and the map goes blank — no error, no warning, and the only explanation the UI offers ("most transfers are not evidenced, by design") will be false.
3. **Two leaks.** `known-entities.ts:131` memoises `null` for every unknown address seen (~12k/hour) and never evicts. `live-client.ts:296-299` starts three intervals and a listener that are never cleared, with no dispose path, so dev HMR and React StrictMode each start a second backfill against rate-limited endpoints.

Also visible today: `atlas.tsx:73` offers all five chains, but `live-client.ts:282` is an all-or-nothing gate, so picking Base, Arbitrum, Tron or Solana renders a **blank map**.

Jake's decisions (2026-09-19): fix the plumbing first and add chains second; evidence Base/Arbitrum as a **hybrid** (first-party Basescan/Arbiscan tags where they exist, otherwise Ethereum plain-account labels reused and clearly marked DERIVED, never contracts); and keep an honest observed-onchain figure via a **declared unfiltered sample** rather than dropping it or paying for the full feed.

## Verified facts that shape the design

- Filtering by registry address uses `topics:[TRANSFER,[…805 padded…],null]` for senders and `topics:[TRANSFER,null,[…]]` for receivers. **Confirmed working** on `eth.drpc.org`, `rpc.mevblocker.io` and `1rpc.io/eth` (25 blocks, 55 KB request, 268 sender-side logs, 166 KB response).
- **The current primary endpoint `eth-pokt.nodies.app` returns HTTP 403 to any large POST body**, including a 200-address batch. It must be demoted for filtered queries and kept only for headers and the unfiltered sample. `ethereum-rpc.publicnode.com` and `eth.llamarpc.com` failed outright from this network.
- Upload is not free: 55 KB per filtered request, two positions per chunk. At 25-block chunks that is ~1.3 MB/hour up, comparable to the download saved. **Chunk size must be raised** until upload amortises; each endpoint's `eth_getLogs` range cap must be measured before freezing the numbers.
- Reduction is uneven: Ethereum ~6× (the registry is Ethereum-centric so many logs match), Base and Arbitrum ~300×. Multi-chain is only affordable filtered.
- Base blocks are ~2 s and Arbitrum ~0.25 s against Ethereum's 12 s, so one hour is 300 / 1,800 / 14,400 blocks. `BACKFILL_BLOCKS` and `SLOT_MS` must become per-chain.
- `eth_getCode` returning `0x` is a definitive, free test for a plain account. EIP-7702 delegated accounts return a 23-byte `0xef0100…` designator and are still key-controlled, so classification is three-way: `eoa` / `delegated` / `contract`.
- The backend already keys evidence `${chain}:${address}` (`store.ts:6`). Matching that convention makes the deferred phase-2 loader a straight insert.
- `aggregate()` applies no chain predicate by design (`engine.ts:41`); filtering is the caller's job, as `demoSnapshot` does via `filtered()` at `engine.ts:76`.

## Phase 0 — honesty and cost, no new chains

Ship this on its own. It fixes what is broken today and puts everything later under test.

**0.1 Extract the pure logic.** New `lib/atlas/live-core.ts` with no fetch, DOM, timers or module-level side effects, exporting `Rec`, `decodeTransferLog`, `formatAmount`, `priceAt`, `makeBlockTimeFn`, `planChunks`, `inferDeposits` (pure: takes records, returns a map, mutates nothing), `pruneRecords`. `live-client.ts` keeps transport, state machine and subscription and calls into it.

**0.2 Add `scripts/verify-live.cjs`**, same compile-then-run pattern as the two existing verifiers. Must assert at least: the inference happy path produces HIGH/0.80 with `INFERRED` in category, source and note; **no inference when either leg is unpriced** (`inferDeposits` sums `usdValue ?? 0`, so this is currently-correct behaviour a future refactor would silently break); out-legs to two clusters, no external in-leg, or sweep-before-receipt each produce nothing; the 80% boundary holds at 79% and 80%; **no cross-chain inference**; inference expires once its records are pruned; `priceAt` returns null rather than a stale sample beyond tolerance; decoding rejects `removed`, wrong topic count, unknown contract, malformed data; amount formatting is exact for 6- and 18-decimal tokens above 2^53; block times are monotonic and interpolate exactly at known headers.

**0.3 Gate the build.** New `scripts/verify-all.mjs` compiles the pure modules to a scratch dir and runs all three verifiers. `package.json` becomes `"build:live": "node scripts/verify-all.mjs && vite build --config vite.live.config.ts"`. This also ends the era of hand-run verifiers nobody runs.

**0.4 Registry expiry — gate and signal.**
- `verify-registry.cjs`: add `BUILD_HORIZON_DAYS` (default 60) and make `admissible(a, now + horizon)` an **error**, not a warning. Any build you publish then stays valid at least 60 days. Keep the existing 150-day warning. Note the trap: `admissible()` also requires a non-negative age, so stamping future dates breaks everything immediately.
- `known-entities.ts`: export `registryHealth(at)` returning `{total, expired, earliestExpiry}`; surface it on `LiveSource` beside the existing `inferredCount()`. In `build()`, prepend a warning to `s.message` once anything has expired and set `s.health='DELAYED'` past 25%. In `atlas.tsx`, extend the `blockingNotice` branch so an empty map caused by expiry says so instead of reusing the by-design copy.

**0.5 Filtered feed (the bandwidth fix).** Replace the unfiltered `getLogs` with two topic-filtered queries per chunk. Reorder the endpoint pool so body-limited endpoints are not used for filtered calls. Raise chunk size until upload amortises, after measuring each endpoint's range cap. Keep the existing bisection retry in `fetchChunk`.

**0.6 Declared sample (the honest denominator).** Every ~10 minutes fetch one small contiguous unfiltered slice (~150 logs), tag those records `feed:'sample'`, and run them through the same `aggregate()` over the sample interval. Add an optional `sample` field to `Snapshot` in `model.ts` that the backend simply leaves undefined. The UI reports observed value and coverage over the stated sampling window — an exact sum with a declared frame, not an estimate. Cost ~1.7 MB/hour.

**0.7 Candidate resolution (keeps inference alive, and improves it).** The filtered feed sees the sweep (unknown → registry wallet) but not the deposit's in-leg, so inference would stop firing. When a poll surfaces a new unknown sender into a registry wallet above a USD floor (suggest $50k), batch those candidates into one `topics:[TRANSFER,null,[…candidates…]]` query over the retained window. This is **better than today**: it is not limited to what happened to be buffered, so inference fires on sweeps whose deposit arrived before page load. Declare the floor in `METHODOLOGY.md`.

**0.8 Stop the silent gaps.** Count failed chunks per feed; expose them in `chainHealth.status` and `s.message`; track `coverageStart` (earliest ingested block time) so the UI can state what the hour actually covers; report `DELAYED` rather than `LIVE` when more than ~10% of a backfill failed.

**0.9 Leaks and fragility.**
- Build the attribution index eagerly at module init from `ADDRESSES`; make `knownAttribution` a pure lookup with **no negative caching**. Bounded by registry size, simpler than the current memo.
- Add `dispose()` to `LiveSource`: hold every timer handle, remove the listener, pass a module `AbortController` to every fetch, guard async loops with a `disposed` flag, reset the singleton. Add `if(import.meta.hot) import.meta.hot.dispose(...)`.
- Replace `prune()`'s head-walk with a filter over the buffer and rebuild the id set; make `range()` take the minimum across buffers. The head-walk silently stops pruning forever on one out-of-order insert.
- `gen-addresses.mjs`: read `checked` from the input and fail on a missing, malformed or future date. Delete the hard-coded literal.
- Fix `.claude/launch.json`'s `dist-check`, which points at a session-specific temp path and works for nobody else. Move the static server into `scripts/`.

**0.10 Cache the aggregate.** `emit()` re-aggregates the whole buffer per listener every 8 s. Memoise per `(window, chain, time-bucket)` so a larger buffer does not burn CPU on a phone.

## Phase 1 — chain-qualify the registry (runtime still Ethereum-only)

The map must render identically at the end of this phase. It only moves the data model.

- `scripts/registry/addresses.txt`: 4 columns → 6, `chain|entity|address|label|checked|note`. Mechanical migration: prefix `Ethereum|`, insert `2026-09-18`.
- New `scripts/registry/probe-code.mjs`: batched `eth_getCode` for every address on Ethereum, writing a date-stamped `code-probe.json` with the three-way `kind`. `gen-addresses.mjs` joins it and **fails** on a missing entry, so a registry with unknown kinds cannot ship.
- `known-addresses.ts`: `ADDRESSES` keyed `${chain}:${address}`, records gain `chain` and `kind`.
- Hoist the explorer map out of `components/atlas.tsx:21` into `geography.ts` as `EXPLORERS` (address and tx URL per chain). Three consumers collapse onto it: `atlas.tsx`, `known-entities.ts:140` (`sourceUrl`), `live-client.ts:222` (inferred-deposit tx link).
- `knownAttribution(chain, address)`; six call sites in `live-client.ts` plus `verify-registry.cjs`.
- Fix two strings that are wrong today and become visibly wrong on Base: `evidenceNote` hard-codes "Etherscan labels this address"; all 70 `ENTITIES[*].source` begin "Etherscan public labels + …", which is an address-level claim inside an entity-level record about jurisdiction. Strip the prefix and let `knownAttribution` compose it per chain. Add a verifier assertion so it cannot regress.

## Phase 2 — Base and Arbitrum runtime

- `evm.ts`: `CONTRACTS` values become `{asset, decimals}`. Every current entry is 6-decimal so behaviour is unchanged, but it retires the `BigInt(1000000)` literal in `live-client.ts:185` and `connectors.ts:11` before an 18-decimal token silently truncates by 10¹².
- `Rec` gains `chain`, `tokenContract` and `feed`. Carrying `tokenContract` off the log deletes `TOKEN_BY_ASSET` rather than making it per-chain.
- Extract a `createFeed(chain, config)` holding the per-chain cursor, endpoint pool, strikes, tip and state; hold them in a `Map`. Price series, inferred map, listeners and `emit()` stay shared. Per-chain config carries endpoints, chain id, slot time, window depth, chunk size and poll interval. Check `eth_chainId` once on connect, as `connectors.ts:34` already does.
- **Per-chain buffers, not one shared buffer.** Three chains at 12 s / 2 s / 0.25 s interleave out of blockTime order, and both `prune()` and `range()` assume sorted. Add a per-chain id set, since the two topic-position queries both return registry→registry transfers.
- Replace the all-or-nothing gate in `build()` with a real generator filter following the `engine.ts:76` convention. **This alone fixes the blank-map bug**, before any Base evidence exists.
- Per-feed `chainHealth`; Tron and Solana stay honestly Not connected.
- Scope inference by `${chain}:${address}` so an address receiving on Ethereum and sweeping on Base infers nothing.

## Phase 3 — Base and Arbitrum evidence

- Probe `eth_getCode` for all 805 addresses on Base and Arbitrum. Emit a generated `DERIVED` list: Ethereum plain accounts with no code on the target chain. Store it as a compact address array, not materialised rows (~20 KB gzipped rather than ~300 KB of source).
- Derived evidence renders as `confidence:'HIGH'`, `score:.8` — the minimum admissible score, the same tier as inferred deposit addresses — with `DERIVED` in category, source and note, and an evidence note stating the key-derivation argument and both code-probe results. It shows as HIGH in the existing confidence composition with no UI work.
- Two limits to state in the note: anyone can send to an address on Base without the owner's cooperation, so a derived receiver is weaker economic evidence; and derivation is EVM-only, never Tron or Solana.
- `verify-registry.cjs` must assert for every derived address: it exists as an Ethereum row, that row's kind is `eoa` or `delegated`, **no first-party row exists for the same chain and address** (first-party always wins), and the composed attribution is admissible and carries the DERIVED marker.
- Then a research wave for first-party Basescan and Arbiscan name tags, ordered by expected presence — Coinbase first, since Base is its own L2 and is heavily tagged there, then Binance, OKX, Kraken, Bitget, MEXC, KuCoin, Upbit, Bithumb and the market makers.
- Update `docs/METHODOLOGY.md` (three feeds, sampled denominator, candidate-resolution floor, the DERIVED tier), `live-lite/README.md` (which still says "Currently Ethereum only", names two retired endpoints and a 50-block chunk size), and `README.md`.

## Verification

1. `node scripts/verify-all.mjs` — model, registry and the new live-core suite, all green; registry gate passes at a 60-day horizon.
2. `node node_modules/typescript/bin/tsc --noEmit`.
3. `corepack pnpm build:live` — verifiers gate the build.
4. **Measure the fix.** Re-run the bandwidth probe in the scratchpad against the built page's query shape and record before/after MB per hour per chain in the commit message. This is the headline claim of the change and must be evidenced, not asserted.
5. Preview `dist-live/` from a nested path with the repaired `dist-check` server: page loads with no 404s, reaches LIVE, corridors appear, and the backfill chip reports real coverage rather than silently short hours.
6. **Exercise the failure path**: point one feed at a deliberately broken endpoint and confirm the page reports DELAYED with a stated coverage start instead of claiming LIVE.
7. **Exercise the expiry path**: run `snapshotAt` with a clock past 2027-03-17 and confirm the page explains the expiry rather than showing an empty map.
8. Chain selector: Base and Arbitrum render real data; Tron and Solana read Not connected. No blank map on any option.
9. Leak check: open the page for 30 minutes, confirm memory plateaus and that a dev HMR reload does not start a second backfill.
10. Mobile at 375×812, and the SVG fallback path.

## Deliberately not in scope

- The phase-2 Cloudflare Workers + D1 backend. Worth noting for later: the 805-address registry is stranded on the wrong side of that boundary — `entity_evidence` has no loader — and Phase 1's `${chain}:${address}` keying makes that loader trivial when the time comes.
- Tron and Solana. Tron needs a keyed TronGrid account; Solana expects a paid indexer.
- The pre-existing lint failures in vendored shadcn components and the map renderers.
- Pruning dormant wallets from the registry. They cost filter size but they are evidence, and evidence is not deleted for convenience.
